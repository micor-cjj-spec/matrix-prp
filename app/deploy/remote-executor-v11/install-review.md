No production/staging credentials, SSH keys, Docker socket, host config, application mounts, privileged device, package installer credentials or network dependencies. Bind only the verified per-job input folder read-only; /tmp is disposable, with the dedicated memory limit. Script output is bounded, not printed by the bridge; output must be encrypted and authenticated before transmission.

Candidate fixed paths:

- /etc/matrix-prp-remote-executor-v11/sandbox.enabled (absent by default; root-owned mode 0444)
- /system.slice/prp-remote-executor-v11.service (dedicated cgroup v2)

Installation review must validate the exact Bubblewrap version and supported flags, user namespace support and existing AppArmor/SELinux policy. Do not disable host security policies to make the launcher work. If unavailable, use a separate disposable VM / isolated hosted CI instead. Preflight verifies non-root identity, root-owned immutable runtime paths, gate content, non-setuid launchers, no nested rootfs mounts, NoNewPrivs, empty effective and bounding capabilities and dedicated cgroup v2 limits. It cannot establish rootfs provenance or all kernel isolation properties; prove those separately.

No root, sudo, Docker group, shared production data or credentials. Separate transport and execution identities if the transport requires networking; never give script access to SSH secrets. Evaluate service read/write protection, file ownership, storage quota and actual process cleanup. The worker is not a general root or staging mutation handler. All live paths are candidates until independent acceptance.

## Minimal installation candidate (review only)

The candidate now provides two fixed local entrypoints, `bridge.py receive-v11` and `executor.py worker-once`. Install root-owned reviewed Python source under the dedicated /opt/matrix-prp-remote-executor-v11 tree and use the system Python with environment and user-site imports disabled (-E -s). Do not use a caller-controlled script path, environment or writable module search path. The receiving SSH login must be dedicated prp-remote-v11, with no supplementary privileged groups, no interactive shell access, no forwarding, no agent, no PTY, no user rc/environment injection, and an administrator-managed forced-command authorized key. Only SSH_ORIGINAL_COMMAND=receive-v11 is accepted. The runner's dedicated private SSH key stays in the trusted GitHub environment. The receiver exclusively owns the private 0700 ledger at /var/lib/matrix-prp-remote-executor-v11. The one-shot worker uses a separate prp-remote-worker-v11 UID/GID and private 0700 /var/lib/matrix-prp-remote-worker-v11. A root-provisioned /run/prp-remote-v11-handoff directory (worker UID, receiver GID, 2750) permits a 0660 worker socket; both peers verify Linux SO_PEERCRED. The worker has no receiver group or access to receiver keys or ledger. The receiver commits the existing authoritative claim before streaming exact manifest-bound input; worker rechecks bytes in a disposable private ledger, returns a bounded claim-bound receipt, and cleans the workdir before success. Disconnect/mismatch leaves authoritative RECONCILE_REQUIRED. No persistent broker, timer, or real SSH activation is supplied. The local handoff-once entrypoint is distinct from receive-v11 and requires both gates; no user-controlled path. No production identity, keys or system paths are reused.

Fixed config directory /etc/matrix-prp-remote-executor-v11 contains administrator-owned `issue` (distinct from #277), `recipient.crt`, `recipient.key`, `signer.crt`, `signer.key`. The public config files use mode 0444; keys use root:dedicated-service-group 0440. Separate encryption and signing identities are mandatory. Protect configuration parents and code against modification by the service account. All three gates (`receiver.enabled`, `worker.enabled`, `sandbox.enabled`) are absent by default, owned by root and must be activated only after separate approval. No marker value is authorization by itself. Configure a dedicated systemd oneshot unit with the exact cgroup name /system.slice/prp-remote-executor-v11.service and hard execution timeout; a separately authorized timer can invoke it periodically. Do not start a timer or create SSH users/keys in offline CI. The worker selects only unexpired VERIFIED jobs bound to a persisted submit request and uses the existing durable atomic claim. No automatic retry after uncertain execution.

Initial retained-manifest reservations: at most 32 jobs and 1 GiB of declared input files; at most 1024 request records. Reservations include terminal/incomplete jobs until separately authorized retention cleanup. This is a logical input reservation, not filesystem quota or a guarantee of available disk; actual disk/inode quota, cleanup policy, expiry handling, WAL/journal/storage overhead, crash reconciliation, rate limits and SSH connection concurrency must be verified before activation. Capacity exhaustion rejects instead of deleting evidence or replay barriers. Do not remove the database or request records as an automatic recovery step.

MVP order: (1) exact-head CI and independent security review, (2) disposable isolated runtime pilot with actual Bash/Python and descendant cleanup, (3) read-only target host preflight, (4) separate authorization for initialization and default-branch workflow promotion, (5) staging-only transfer/execute/query E2E. The workflow in this PR is still blocked-only; no secrets, issue posting, installation, timer or live dispatch is configured. #396 read-smoke and all image import/restart operations stay outside the MVP. Never interpret this document or any CI result as approval to install or enable the service.

### P6.3 physical storage, retention and recovery (candidate only)
The spool's declared reservation remains capped at 1 GiB; P6.3 adds a separate 1 GiB application-level physical artifact cap and a real filesystem free-space/inode check before accepting a manifest and before each streamed file. At least 512 MiB and 1,024 inodes must remain available. All spool scans reject symlinks, hardlinks and special files. This is not a kernel-enforced project quota and cannot prevent unrelated host processes from consuming the filesystem; host-level monitoring and capacity controls remain required.

Receiver recovery runs only after the request's independent Owner approval, under the existing SQLite writer lock; the fixed local handoff also performs recovery before dispatch. Orphan .partial files are removed; expired RECEIVED/TRANSFERRING/VERIFIED jobs become CANCELLED; a RUNNING job is changed to RECONCILE_REQUIRED only when its dedicated worker cgroup is empty and the 180-second grace period elapsed. Uncertain work is never retried. After 24 hours, artifacts for SUCCEEDED, FAILED, TIMED_OUT, CANCELLED or REJECTED jobs are purged. SQLite job rows, original job IDs/nonces, result receipts and every request/comment replay record are retained; the artifacts_purged marker only releases active spool capacity. Cleanup is idempotent across crashes. Debian 13 disposable-VM tests exercise actual filesystem accounting, partial cleanup, terminal purge and result retention. No actual SSH, production server, credentials, host installation, activation, merge or deployment. Independent security review and separately approved live activation remain outstanding.
