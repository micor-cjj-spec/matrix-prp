This package is an offline-reviewed candidate, not an installation request. No actual domain, issuer, identity, grant, TLS certificate, account, route, credential or host is provisioned. No command is to be run against a target before M06 approval.

## Configuration and identities
- Dedicated nonproduction resource host HTTPS /mcp; distinct issuer host with realm /realms/prp-ops-staging; separate confidential introspection client prp-ops-staging-resource. Do not modify existing shared realm/client, production resource, health tools or business databases. Verify exact client identity, audience, issuer, scope, introspection claims and OAuth authorization-code/PKCE/CIMD/refresh interoperability first; actual issuer may not match this candidate and must be reviewed. No claim that naming a realm proves isolation.
- profile.json.example is deliberately rejected (.invalid). A future root operator provisions exact profile.json 0644 root:root in /etc/matrix-prp-ops 0755 root:root, and only upon explicit approval provisions ENABLE_MCP_PROFILE 0644 with one line profile-sha256=<sha256 of exact approved profile bytes>. No marker file in repository. Root ownership, single link, no symlink, bounded strict schema, ancestor checks and digest are verified; root/backup rollback not prevented. Independently provision ALLOW_HOST_METRICS only after approval of actual host-wide disclosure boundary. Both markers must remain absent before M06.
- prp-ops-collector and prp-ops-mcp distinct nonroot UIDs. Reader private primary group prp-ops-mcp, supplementary prp-ops-snapshot. Grant root:prp-ops-mcp 0640 in fixed configuration directory; grant lifecycle admin only, independent root-owned lock, initial inactive seed must be separately approved. The runtime has no grant writer. Snapshot directory collector:prp-ops-snapshot 2750, file 0640. Audit directory reader-owned 0700, access.jsonl 0600. No shared business path.
- Systemd LoadCredential supplies separate root-managed TLS certificate/key and confidential introspection secret; do not store in profile, repo, environment, command line or chat. Exact read-only credential mount semantics and cert chain verified on target before install. Secret format is ASCII 1-512 bytes without newline.

## Process/ingress
- prp-ops-mcp.service is a template with no Install section, Restart=no, nonroot, strict filesystem, no capabilities, fixed reader write path only; launcher rejects root, CLI overrides, missing/changed profile and host disclosure gates. Default ASGI factory remains inert. Runtime dependency wheel lock previously tested in Python3.12 Linux CI; target OS/Python compatibility not yet known. Code and venv must be root-owned/nonwritable by service identities. Never run CI fixture as deployed service.
- Launcher candidate binds ONLY 127.0.0.1:18444 TLS, one Uvicorn process, fixed h11, no proxy headers, no access log, no WebSocket. Owner's read-only listener check found 18444/18445 unoccupied at the sampled instant and 18443 occupied by an existing service. This is not a port reservation: recheck immediately before an independently approved install; on bind failure stop, do not fall back or evict listeners. Existing wildcard IPv4/IPv6 HTTPS listeners make the separate TCP passthrough template NO-GO for this target. A distinct resource hostname on the existing Nginx HTTPS listener is a candidate only; see below. Do not edit/reload shared Nginx without separate explicit approval. Verify DNS, public trust chain, actual HTTP protocol, connection/read timeouts, total rate limits, IPv4/IPv6, firewall egress limited to approved issuer and loopback access. Uvicorn and systemd sandbox are not a firewall.
- Service checks profile digest + disclosure at startup and around successful requests. Remove either marker first for emergency denial; then stop isolated service/timer, revoke local grant and issuer tokens, confirm no active connections. In-flight sends still have residual race; no hard watchdog or tamper-proof audit. Stuck synchronous worker requires operator stop/kill under bounded TimeoutStopSec; explicit restart only after reapproval. Host/network/issuer failure can make service unreachable. No automatic recovery to old approved config.

No default host or existing location changes. If shared Nginx modification is not authorized or compatibility fails, stay NO-GO and reconsider a separately approved independent ingress.
