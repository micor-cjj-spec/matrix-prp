## Process/ingress
- prp-ops-mcp.service is a template with no Install section, Restart=no, nonroot, strict filesystem, no capabilities, fixed reader write path only; launcher rejects root, CLI overrides, missing/changed profile and host disclosure gates. Default ASGI factory remains inert. Runtime dependency wheel lock previously tested in Python3.12 Linux CI; target OS/Python compatibility not yet known. Code and venv must be root-owned/nonwritable by service identities. Never run CI fixture as deployed service.
- Launcher binds ONLY 127.0.0.1:18443 TLS, one Uvicorn process, fixed h11, no proxy headers, no access log, no WebSocket. Separate ingress candidate in prp-ops-stream.conf.example uses TCP passthrough to preserve raw HTTP headers and TLS scheme; dedicated address/443 and matching public certificate required, cannot coexist on the same listener with current shared HTTP Nginx without separate design. Example address is documentation-only. If no independent ingress is available, stay NO-GO; do not edit production Nginx. Verify DNS, public trust chain, actual HTTP protocol, connection/read timeouts, total rate limits, IPv4/IPv6, firewall egress limited to approved issuer and loopback access. Uvicorn and systemd sandbox are not a firewall.
- Service checks profile digest + disclosure at startup and around successful requests. Remove either marker first for emergency denial; then stop isolated service/timer, revoke local grant and issuer tokens, confirm no active connections. In-flight sends still have residual race; no hard watchdog or tamper-proof audit. Stuck synchronous worker requires operator stop/kill under bounded TimeoutStopSec; explicit restart only after reapproval. Host/network/issuer failure can make service unreachable. No automatic recovery to old approved config.
