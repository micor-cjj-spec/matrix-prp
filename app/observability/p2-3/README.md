# P2.3 restricted container resource spike (#450)

Offline-only GitHub-hosted Linux amd64 runner with cgroup v2. P1 running pilot and all existing services/branches remain unchanged. Official cAdvisor v0.60.1 and P1 Prometheus v3.13.5 resolved to actual registry digests at test time, Python fixture image test-only. No deployment or vulnerability clearance.

## Permission envelope
Non-root cAdvisor (65534), cap-drop ALL, no-new-privileges, read-only filesystem, no devices, no privileged, no host PID/network, no Docker socket, no host rootfs, /var/lib/docker or /var/run mounts. Only the disposable runner's /sys/fs/cgroup mounted read-only with host cgroup namespace for cgroup discovery; this still exposes runner cgroup metadata to cAdvisor, not a per-cgroup filesystem security boundary. No container labels/env metadata collected. Raw factory prefix selects only the synthetic fixture's exact cgroup, with root stats disabled. Raw cAdvisor HTTP API itself is not an access-control boundary and not published; test Prometheus projects only a fixed synthetic identity, fixed metric families and allowed labels, no raw cgroup ID persisted. No real target or real credentials. Never copy this to the actual host.

## Acceptance
Check cgroup v2, exact disposable workload cgroup and limits; compare cAdvisor CPU delta, memory current and memory/CPU limit with kernel files. Verify a bounded synthetic load, no raw fixture marker labels, projected TSDB series, fresh scrape and exit/restart identity semantics, resource snapshot, no ports/socket/privilege, unrelated network denied. Record block IO availability against actual kernel io.stat; absence/mismatch is reported as unsupported, not zero I/O. Raw handler has no container PID/network or filesystem view. OOM-kill event routing depends on kernel log access (not permitted), so omit OOM event metric and do not claim zero OOM kills. Memory pressure events, if present, are distinct. No direct Docker lifecycle metadata or name mapping; cgroup identity is test-only. No automatic widening on failure. Dashboard is a candidate JSON for later review, not imported into live Grafana. CI measurements are not actual host peak load or storage forecasts.
