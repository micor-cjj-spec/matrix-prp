# Finance V3 P0 · 微信支付 XLSX 账单安全导入

## 范围与约束
- **仅实现微信官方“全部账单” XLSX 文件**；支付宝、京东、云闪付和银行卡分别使用独立 Parser，待真实样例验证后逐一实现。
- 上传不等于入账。解析后只创建导入批次和暂存行；用户必须映射实际扣款资金账户并点击确认，才会创建财务流水。
- 只将“商户消费 + 支出 + 支付成功 + 有唯一源交易单号”的普通消费标记为 READY。全额退款/退款入账、转账、红包、状态不明的流水保留为 REVIEW，不自动入账；跨平台关联属于后续版本。
- 原始文件不落盘、不发送 AI、不提交 Git 仓库，只保存与对账必要的规范化字段。文件大小不超过 5 MiB，行数不超过 20,000。
- 账户必须属于当前 JWT 用户、未删除且为 CNY；通过支付方式映射到真实 PRP 账户，**不得把微信支付当成余额账户来自动猜测**。
- 不使用邮箱或手机号等信息做用户匹配；前后端保持旧财务 API 兼容。

## 服务端 API
- `POST /api/finance/imports/wechat/preview`: multipart `file`, optional `sourceAccountKey`。相同 SHA-256 文件+来源账号返回历史批次。
- `GET /api/finance/imports`: 登录用户最近 20 次导入记录。
- `GET /api/finance/imports/{id}`: 当前用户导入预览与各处理状态。
- `POST /api/finance/imports/{id}/commit`: JSON `{"paymentAccounts":{"零钱":123}}`。事务中校验用户、账户币种、来源唯一标识，逐条把 READY 消费写入 V2 收支账本与 source link；重复点击不会多记账。未映射账户的 READY 流水保持待入账。

## 新建表和数据保护
V19 只 CREATE：
- `prp_finance_import_batches`：平台、来源账号、文件哈希、文件名、状态。
- `prp_finance_import_rows`：每笔来源流水及 REVIEW/READY/DUPLICATE/POSTED。
- `prp_finance_source_links`：与 `prp_finance_transactions` 的最终关联及 DB 唯一索引。

不执行历史财务表的 ALTER、UPDATE 或 TRUNCATE，不修改旧行 ID、金额、交易日期、账户关联。删除已入账账单不会自动冲销账面交易（本期没有批次撤销功能）。

## 本期限制 / 后续
- REVIEW 无人工强制过账接口，避免错误退款/转账影响净消费。后续以匹配原始订单与真实账户双向账本的方式支持退款、转账、红包及跨平台去重。
- 本期自动分类暂设为“待分类”，用户可通过现有财务明细界面修改；后续增加商户规则和分类建议。
- 不自动发现跨平台重复：银行卡消费与微信流水的同一笔资金事件需要多来源关联模型才可安全去重，**导入第二个平台之前须完成对账模块**。
- 不提供银行账号直连或真实支付，账户期初余额必须按账单期初时点校准，不能把当前余额当成历史期初。
