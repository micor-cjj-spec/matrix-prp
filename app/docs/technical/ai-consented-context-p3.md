# Matrix AI P3 — 每次明确授权的只读业务摘要

## 本次功能

用户在 Web/PWA「聊天」选择特定数据域，再点击 **预览共享内容** 查看服务端生成的精简快照，最后明确点击 **同意仅本次发送**。选项默认全部关闭、请求结束后清空。没有同意就拒绝带 scopes 的聊天请求（400）。

仅三类 allowlist 查询（均通过既有当前用户业务 Service，无客户端 userId、SQL、任意 URL、实体 ID 或工具参数）：

- `tasks`: 待办总数、今日/逾期/7 日到期计数，以及最多八条今日和逾期任务的标题、状态、优先级、日期。不发送描述、附件或其它数据。
- `practice`: 刷题累计、正确和错误计数。不发送题目、答案、学科笔记及其它个人数据。
- `wellness`: 本日摄入热量、蛋白质、餐次、活动分钟数。不发送体重、身体指标、病历、餐次/运动备注或个人健康档案。

### 核心保证与局限

- 服务端总会按当前 JWT 解析的用户身份读取。即使前端被篡改也无法指定其他账户或额外 scope。
- `/api/ai/context/preview` 与 `/api/ai/chat/stream` 在后端独立校验 allowlist；实际发送时重新采集快照，因此**预览与最终发送之间的数据可能变化**。敏感情况下请暂停发送、更新数据后再次预览。
- 明确 scope + `contextConsent=true` 只授权**当前单条消息**，无跨消息持久授权。生成的 JSON 快照仅注入给当前模型的请求，不写入聊天消息内容。**模型回答可能包含其引用的数据，因此已有聊天历史仍会包含模型生成的回答。**
- 发送到用户当前选择的服务商（可能是第三方 API）。摘要作为不可信引用数据呈现，标题中的提示词不应被当作工具指令。内容限制最大 6000 字符并继续纳入原有按用户与全站额度限制。
- 普通聊天完全兼容；空范围不查询业务数据。没有授权时不得调用任何业务工具。OpenClaw 的管理员专属 Gateway 仍保持隔离，P3 不授予它新工具、网络或数据库权限。
- 尚不支持自动多步 tool-calling、修改任务、写入健康日志、触发提醒或 Git/Codex 操作。所有操作型工具留待权限审计和专门审批工作完成后开发。
- 因无需持久授权表，本次**无 Flyway 迁移**，V1-V10 不变。GitHub 合并不等于生产验收。

## 验证

CI：后端用户隔离测试（独立账号任务不交叉）、scope 拒绝、无授权不读业务数据、精简快照不包含任务描述和体重、数据不直接写入用户聊天记录；Web/PWA 类型检查与构建、原有 MySQL 及 V10 Flyway 回归。

生产部署前应先完成历史 V8/V9/V10 数据库迁移和备份恢复演练；确认模型 API Key、SSE、PWA、按量收费提醒与现有业务页面正常。第三方模型的真实 API 调用需另行单独验收。
