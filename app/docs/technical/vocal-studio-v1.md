# PRP 声乐工作台 V1

## 本次范围

本次在现有 `/vocal` 与 `prp_vocal_takes` 基础上迭代，不引入数据库迁移、不删除既有录音，也不改变用户隔离和 AI 配额策略。

- 修复低音量输入容易被误判为无音高的问题：RMS 噪声门由 0.018 下调至 0.003，并增加低音量周期信号与静音回归测试。
- 在用户点击录音后，尽可能于等待 iOS 麦克风权限提示之前创建并恢复 AudioContext；若浏览器无法提供音频分析，仍允许 MediaRecorder 录音。
- 通过零增益节点让 Web Audio 分析图持续渲染，不将麦克风声音回放到扬声器，降低 Safari 上分析器挂起的风险。
- 使用浏览器默认麦克风约束，避免强制关闭回声消除/降噪后触发不兼容的采集路径。
- 录音停止后先在设备本地预览，由用户明确确认后再上传；显示输入电平、音轨状态、录音大小和可操作的提示。
- 区分音轨不可用、实时输入偏低、没有稳定音高、录音保存失败等情况。音高检测没有结果不等于录音没有声音。
- 将声乐页改为工作台：练习统计、今日练习计划、当前目标曲目、录音预览和历史复盘。目标曲目目前仅作为练习入口与备注，不冒充已实现的持久化歌曲库。

## 技术边界

- iOS Safari 的麦克风权限图标只表示浏览器已启动采集会话，不能证明录到可听声音。
- RMS 电平是设备端相对幅度，不是经过校准的声压级。
- 当前音高仍由浏览器端估算。复杂伴奏、多声部、气声、滑音和噪声可能导致无结果或误判。
- 当前 AI 教练仍只接收练习类型、文字备注与设备估算指标，不接收原始录音；不能声称已听过录音。
- 本次代码与自动化测试不能替代 iPhone 实机验收。必须验证本机预览与上传后的回放都有声音后，才可认定录音链路修复。

## iPhone Safari 实机验收

1. 使用 HTTPS 登录 PRP，打开“声乐训练工作台”并允许麦克风权限。
2. 点击开始录音，轻声哼鸣 3–5 秒，确认输入电平会随声音变化；如持续为零，检查音轨状态与系统麦克风权限。
3. 点击结束录音并试听，在本机预览中确认有可听声音，再确认保存。
4. 保存成功后从训练记录播放服务器录音，确认声音与本机预览一致。
5. 用正常音量与轻声各测试一次；轻声可能没有稳定音高点，但只要预览有声音，不应被提示为“没有录音”。
6. 分别在麦克风权限被拒绝、系统静音/输入中断、切换应用返回等场景验证错误提示和资源释放。
7. 在 Android Chrome 和桌面 Chrome 做基本回归，确认录音、预览、保存、播放、删除与 AI 训练建议仍可用。

## 后续阶段

### V1.1：持久化歌曲练习

- 新增个人歌曲库、段落与练习重点。
- 将录音关联到歌曲和段落，支持同一段落的多版本对比。
- 为迁移增加数据保留测试，并完成部署控制器兼容性审查。

### V1.2：训练会话与线下课程

- 记录一次训练会话、目标、完成情况和复盘。
- 记录线下课程、老师反馈与课后作业。
- 将作业转为可追踪的后续练习任务。

### V2：服务端音频分析

- 在独立可重试的后台任务中做音频 DSP 与有参考旋律时的对齐。
- 为每项结果记录算法来源、置信度、时间点与异常状态。
- 仅在所选模型明确支持音频输入时提供模型音频反馈，并与客观测量分开呈现。
