# Matrix PRP — 自定义提醒与 Web Push（P0 草案）

## 功能
- 每个登录用户管理自己的提醒：立即发送、指定时间、每天、工作日、每周指定星期、每月指定日期。
- 提醒按 IANA 时区解释，服务器统一以 UTC 储存下次触发时间。
- 消息中心在服务器保存通知，设备未允许 Push 时仍可查看。
- Web PWA 用户主动启用系统推送；iOS 16.4+ 必须在主屏幕安装并以 Web App 方式打开。
- Web Push 投递记录和最多 5 次指数退避重试；多设备按用户绑定，按授权设备投递。

## 配置步骤
1. **先备份、验证恢复**，在已存在 MySQL 数据卷上手工执行 `app/docker/mysql/init/004-notification-center.sql`。初始化目录的脚本不会自动在旧数据卷上重跑。
2. 生成 VAPID P-256 密钥对；将 **Base64（非 PEM）格式**的 65 字节非压缩公钥和 32 字节私钥写入环境变量 `MATRIX_PRP_VAPID_PUBLIC_KEY` 和 `MATRIX_PRP_VAPID_PRIVATE_KEY`；**不可提交密钥**。保持跨重启不变，否则需重新订阅。
3. 通过真实域名 HTTPS 服务访问 Web 端（本机 localhost 可用于开发）。保证 /sw.js、/manifest.webmanifest、/api/** 与页面在同一安全源下可访问。
4. 从 Web「消息与提醒」按钮请求浏览器通知授权、登记设备，点击测试消息后查看系统通知和站内收件箱。
5. 测试 iPhone Safari 主屏幕 PWA、Chrome/Edge、用户 A/B 隔离、失败重试、时区与服务器重启。

## 范围与风险
- 新增第 004 次 SQL 迁移；不自动上线、不修改现有数据。
- 默认只有自己给自己发送；跨用户发送、免打扰、精细化设备筛选、通知模板推迟到 P1。
- 调度 30 秒轮询；多实例采用数据库条件更新领取规则，至少一次投递语义。网络成功与手机显示并不等价。
- 已对浏览器 endpoint 的 HTTPS 和已知推送提供商域名进行校验；应补充部署网关限流与审计。
- 生产上线前需要真实数据库、浏览器和 iPhone 实机端到端验证。


## 安全：退出登录
Web 端主动退出时，先从服务端解除当前浏览器端点，再调用 PushSubscription.unsubscribe()。
如在断网状态下无法解除订阅，浏览器上的旧订阅可能持续收取旧用户的推送，用户应当在系统通知设置里关闭该应用通知，并在重新登录后手动移除旧设备。长期方案需增加服务端会话关联和设备强制解绑策略。
