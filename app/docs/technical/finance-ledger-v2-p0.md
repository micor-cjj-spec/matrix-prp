# Matrix PRP 财务 V2 / P0：账户账面余额与内部转账

## 定位与范围
本阶段只实现个人账面资金核算，不接入银行或移动支付账号，也不执行真实付款。

- **本月结余** = 本月收入 - 本月支出，只描述收支净额，不是账户余额。
- **账户账面余额** = 期初余额 + 截至今天该账户全部收入 - 全部支出 + 内部转入 - 内部转出。
- 不同币种不汇总、不自动转换；跨币种转账直接拒绝。
- 内部转账保存在独立表，不计入月度收入、支出或消费占比。
- 本阶段为 Web/PWA 增加转账记录与余额视图；旧 Mobile 快速收支记账保持兼容，独立 uni-app 转账页面暂不在本期。
- 不做预算、负债、投资、银行同步、自动抓取账单或 AI 查询财务数据。

## 数据模型与兼容
- 新增不可变账户关联 `prp_finance_transactions.account_id`（可空以兼容旧数据）。
- V13 为旧流水按 `user_id + account` 映射现有有效账户。没有账户资料的旧流水，以**零期初余额**自动建立同名账户并做核对标记；不猜测真实银行余额，不修改旧流水金额。
- 旧 REST 路由、请求中的 `account` 字符串及响应字段保持原样。旧客户端传入新账户名称时后端自动创建零期初账户并写入稳定 `account_id`。
- 现有行保留 `account` 名称作为历史快照；以后改账户名称不会改变该旧快照，但所有新余额计算均依赖稳定 ID。
- 转账表独立保存来源账户 ID、目标账户 ID、金额、币种由账户决定、日期、备注、用户和请求幂等键。
- 转账只支持两个归属当前用户的有效账户，金额 > 0，同币种、非未来日期、不能同账户转账。客户端重试时使用同一个 `clientRequestId`；数据库联合唯一索引防重复。
- 有活动收支或内部转账的账户禁止删除；已有流水/转账的账户禁止修改币种。调整历史金额或期初余额应谨慎并核对。
- 所有数据读写继续按 JWT 用户隔离，不接受传入 userId。物理唯一性不代替后端所有权校验。

## 部署：必须先处理数据库，后发布依赖 V13 的 Java 程序
1. 确认服务器目前的 `matrix_prp` 迁移状态，核对 `flyway_schema_history` 是否完整到 V12。此前的 `MATRIX_PRP_FLYWAY_ENABLED=false` 是有意关闭，**不能因为代码合并就改成 true**。
2. 停止写入并备份 MySQL、视频目录、systemd 配置；只有一个云磁盘时，备份要存到其他故障域。先在另一套 MySQL 上做真实恢复并演练回滚。对比行数、账户余额、用户隔离。
3. 按 `safe-db-migrations-p0.md` 核对旧库 V1–V7 基线，使用适配现有 Flyway 状态的**增量迁移**执行 V13，绝不可执行 `clean`、自动 baseline、重建库、删除 Docker volume 或重放 V1–V7。V13 DDL 与补录账户语句需先在还原副本验证。
4. 上线前记录 `prp_finance_transactions` 行数/总金额和按账户明细，再执行 V13，核对 `account_id IS NULL` 的**活动**流水数、自动补录账户数和账户属主匹配情况：
   ```sql
   SELECT COUNT(*) FROM prp_finance_transactions WHERE deleted=0 AND account_id IS NULL;
   SELECT COUNT(*) FROM prp_finance_accounts WHERE deleted=0 AND note LIKE '由历史收支流水自动补录%';
   SELECT COUNT(*) FROM prp_finance_transactions t JOIN prp_finance_accounts a ON a.id=t.account_id
    WHERE t.deleted=0 AND (t.user_id<>a.user_id);
   ```
   预期第一和第三个计数均为 0；第二个为需人工核对期初余额的账户数。
5. 迁移后部署 Java，再部署 Web 构建（保持 /prp/ 子路径）。验证旧 Web/Mobile 记账、账户重命名、同币种转账、跨币种拒绝、跨用户隔离、月度统计不变、转账幂等和 iPhone PWA。
6. 升级失败时先停止写入和服务，将应用回退并从已验证的备份**恢复到迁移前一致状态**。V13 包含 DDL，不提供一键反向删除数据的 SQL；禁止直接 DROP 新列或表而忽略已录入的转账。

## 后续边界
- V2 P1：账户对账及余额调整单、服务端幂等冲突处理、跨账户统一财务流水、银行卡余额导入。
- V2 P2：预算与定期账单、财务目标、资产负债结构。
- V2 P3：用户逐次授权的只读财务摘要与 AI 分析。
- 当前按账户/交易扫描聚合适用于小规模个人数据；数据量上升应升级为数据库侧按账户聚合与分页，避免应用内读入全量记录。
