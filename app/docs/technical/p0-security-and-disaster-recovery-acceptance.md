# P0 生产数据安全与恢复验收清单

适用：Matrix PRP 单机部署（Nginx + systemd + Docker MySQL + 本地视频文件）。本清单不自动触碰生产环境；管理员执行并留下验收记录。

## 已有防护与审计结论

- `/api/video/media/{id}` 虽然在 Spring Security 中允许匿名访问，控制器仍要求签名 `ticket`，服务层再次根据票据内的用户 ID 查询归属视频，且票据会过期。必须同时核查 Nginx 的 `/_internal_prp_video/` 位置配置为 `internal`，不能暴露媒体目录的其他公网别名。
- `WellnessAiDraftService.confirm` 已经是事务方法；草稿读取采用 `FOR UPDATE`，同一用户餐次写入前会锁定用户行，并通过 `PENDING -> CONSUMED` 状态控制重复确认。仍需在真实 MySQL 环境进行并发与异常回滚回归。
- 自动发布包含在线数据库备份、隔离库恢复/迁移预演和健康检查，但**一次部署的备份并不等于独立、定期、异地的灾难恢复能力**。

## 异机备份实现（按需安装）

已有可审计的安装说明与独立加密备份工具：[PRP 异机备份操作手册](offsite-backup-operations.md)。脚本及 systemd 模板在 `app/deploy/`。这不是自动安装；服务器管理员配置远端 S3 存储、Restic 独立密钥和告警 Webhook 后，应完成一次真实备份、一次隔离恢复及告警送达验收，方可关闭灾备 P0。

## 必须由管理员落实的生产备份策略

1. 独立于自动部署，每天生成 MySQL 一致性备份，保留最近 7 天每日备份和最近 4 周每周备份；根据实际数据量调整。备份任务失败必须告警。
2. 同步备份视频存储根目录、必要的知识文件和应用配置。视频备份与数据库快照应记录同一恢复点，以避免数据库引用不存在的媒体文件。
3. 至少保留一份不在生产服务器同一磁盘、同一故障域的副本；备份目录和私钥仅对受信任管理员开放，备份静态加密。禁止将数据库、视频、JWT 密钥或 API Key 上传到 GitHub Actions artifact 或公开仓库。
4. 对备份记录时间、数据库版本、文件数量和每个归档的 SHA256；定期检查校验和。数据库备份要包含必要的字符集、存储过程/触发器（若存在）和一致性参数。
5. 每月在**隔离环境**进行完整恢复演练：先恢复配置与数据库，再恢复媒体文件，验证 Flyway schema_version、登录、AI 会话、健康餐次、财务记录、视频的权限及 HTTP Range。
6. 设置可衡量目标：建议首期 RPO ≤ 24 小时、RTO ≤ 4 小时；若达不到，记录实际恢复用时和改进措施。以上目标只有演练达标后才能声称得到保障。

## 上线前 P0 负向验收

| 用例 | 预期结果 |
| --- | --- |
| 用户 A 使用用户 B 的视频 ID 获取 playback | 服务端拒绝或返回 404 |
| 改写视频 ticket 中的任意字节 / 请求不同视频 ID | 403，不能返回视频文件或 X-Accel-Redirect |
| ticket 过期后再次请求新 Range | 403，客户端应重新获取授权播放地址 |
| 直接请求 `/_internal_prp_video/...` | Nginx 拒绝访问 |
| 双击 AI 饮食草稿确认、并发请求同一草稿 | 最多一次成功，其余冲突；无重复数据 |
| 同一用户不同草稿同时写入相同日期、餐次 | 最多一次成功，失败批次整体回滚 |
| 模拟 AI 写入事务中途抛异常 | 草稿未消费，业务数据未部分落库 |
| 备份中缺少视频或文件 SHA256 不匹配 | 恢复演练失败并告警，不得标记成功 |

## 记录与发布门槛

- 记录演练日期、执行人、独立恢复环境标识、数据库 schema、备份 SHA256、恢复耗时、失败处理与工单链接。
- 上述各项未实际验证前，**不得**宣称已完成生产灾难恢复治理。
- 若必须修改 Nginx 或 systemd，只能通过受控管理员操作并保留原配置及回滚路径；不要通过应用 PR 自行修改生产机。
