# 一期产品设计

## 1. 一期目标

一期目标不是一次性做完整的个人管理系统，而是先做出一个每天可用的个人资源管理闭环。

核心闭环：

```text
登录 -> 查看今日状态 -> 快速记录 -> 管理任务 -> 记录财务 -> 查看知识库 -> 周期复盘
```

一期完成后，Matrix PRP 应该能够回答三个基础问题：

- 我今天需要关注什么？
- 我最近发生了什么、做了什么、花了什么？
- 我的知识库资料能不能在新平台里被找到和使用？

## 2. 产品定位

Matrix PRP 一期定位为个人资源管理平台的基础版，先服务单个用户。

它不是单独的记账软件、待办软件或笔记软件，而是把个人生活中的多类资源放到同一个工作台里：

- 记录：沉淀每天发生的事情。
- 任务：承接下一步行动。
- 财务：记录基础收入和支出。
- 知识：接入现有 Markdown 知识库。
- 复盘：形成周期性回顾入口。

一期重点是打通公共能力，不追求每个领域模块的深度。

## 3. 用户画像

一期默认用户是项目 owner 本人。

典型使用习惯：

- 白天通过 Web 查看状态、整理任务、补充记录。
- 手机端用于快速记录、快速记账、查看今日状态。
- CLI 用于开发者式快速录入、搜索和自动化。
- 原有 `knowledge/` 目录继续作为长期知识资产。

## 4. 一期范围

### P0 必做

- 登录和 JWT 鉴权。
- Dashboard 今日工作台。
- 通用记录管理。
- 标签管理。
- 任务管理。
- 财务流水和月度汇总。
- 复盘管理。
- 知识库目录浏览、文件查看和基础搜索。
- Web 主应用。
- 后端 REST API。
- MySQL Docker Compose 本地环境。
- OpenAPI / Swagger UI 接口文档。

### P1 建议做

- 记录按模块、标签、日期、关键词筛选。
- 任务按状态、模块、日期、优先级筛选。
- Dashboard 展示逾期任务和高优先级任务。
- 财务按分类汇总。
- CLI 覆盖登录、模块、标签、记录、任务、财务、复盘和知识搜索。
- Mobile 覆盖登录、今日状态、快速记录、快速记账。
- 统一验证脚本。

### P2 后续再做

- 完整社交关系管理。
- 完整学历/学习计划管理。
- 完整工作项目管理。
- 生活习惯追踪。
- App 推送提醒。
- AI 自动分类和复盘。
- 知识库在线编辑。
- 多用户、组织、复杂权限。

## 5. 端侧分工

### Web

Web 是一期的主战场，承担完整管理能力。

页面范围：

- 登录页。
- Dashboard。
- 记录页。
- 标签页。
- 任务页。
- 财务页。
- 复盘页。
- 知识库页。

体验原则：

- 首页像工作台，不像营销页。
- 表单字段够用即可，优先保证录入速度。
- 列表支持筛选、空状态和清晰操作入口。
- 重要信息优先展示数量、日期、金额、状态。

### Mobile

Mobile 一期只做轻量动作。

能力范围：

- 登录。
- 今日概览。
- 快速记录。
- 快速记账。
- 完成今日任务。

暂不做复杂列表管理和深度配置。

### CLI

CLI 服务快速录入和自动化。

能力范围：

- 登录和查看配置。
- 查看 Dashboard。
- 模块、标签查询与维护。
- 新增、查询、更新、删除记录。
- 新增、查询、更新、删除任务。
- 新增、查询、更新、删除财务流水。
- 月度财务汇总和分类汇总。
- 新增、查询、更新、删除复盘。
- 知识库搜索。

## 6. 核心模块设计

### Dashboard

Dashboard 是每天打开系统的第一屏。

展示内容：

- 今日任务数量和列表。
- 逾期任务数量。
- 高优先级任务列表。
- 最近记录。
- 本月收入、支出、结余。
- 记录、任务、财务、知识、复盘模块入口。

### Records

通用记录用于承载生活、学习、工作、兴趣、社交、财务等模块中的过程数据。

字段：

- 标题。
- 内容。
- 所属模块。
- 记录日期。
- 标签。

一期能力：

- 新增记录。
- 查看记录列表。
- 编辑和删除记录。
- 按模块、标签、日期、关键词筛选。
- 展示记录关联标签。

### Tags

标签用于跨模块归类。

字段：

- 名称。
- 颜色。
- 说明。

一期能力：

- 创建标签。
- 查看标签。
- 编辑和删除标签。
- 记录绑定标签。
- 记录按标签筛选。

### Tasks

任务用于管理下一步行动。

字段：

- 标题。
- 描述。
- 所属模块。
- 优先级。
- 截止日期。
- 状态。

状态：

- `todo`
- `in_progress`
- `done`
- `canceled`

一期能力：

- 新增任务。
- 编辑和删除任务。
- 修改任务状态。
- 按状态、模块、日期、优先级筛选。
- Dashboard 展示今日、逾期和高优先级任务。

### Finance

财务一期只做基础流水和月度汇总。

字段：

- 类型：收入 / 支出。
- 金额。
- 分类。
- 账户。
- 日期。
- 商户或对象。
- 备注。

一期能力：

- 新增交易。
- 查看交易列表。
- 编辑和删除交易。
- 按月份、类型、分类筛选。
- 查看月度收入、支出、结余。
- 查看支出分类汇总。

### Knowledge

知识库一期不迁移、不在线编辑，先接入已有 Markdown 文件。

能力：

- 读取 `knowledge/` 目录树。
- 打开 Markdown 文件。
- 轻量预览 Markdown 标题、列表、引用和代码块。
- 基础搜索文件名和内容片段，并展示搜索评分。

### Reviews

复盘一期先作为轻量入口。

字段：

- 类型：weekly / monthly / module。
- 标题。
- 总结。
- 亮点。
- 问题。
- 下一步行动。
- 所属模块。
- 复盘周期。

一期能力：

- 新增复盘。
- 查看复盘列表。
- 编辑和删除复盘。
- 按类型、模块、周期筛选。

## 7. 数据对象

一期核心对象：

- User
- Module
- Record
- Tag
- RecordTag
- Task
- FinanceTransaction
- Review
- KnowledgeFile

设计原则：

- 用户数据表预留 `user_id`。
- 通用对象优先复用，不为每个模块重复造一套表。
- 先保证 REST API 清晰稳定，再考虑 OpenAPI 生成 SDK。

## 8. 一期验收标准

一期完成的判断标准：

- 可以通过 Docker Compose 启动本地 MySQL。
- 后端可以启动，业务 API 需要 JWT 鉴权。
- OpenAPI JSON 和 Swagger UI 可访问。
- Web 可以登录并进入 Dashboard。
- Dashboard 能看到任务、记录、财务、知识和复盘入口。
- 可以新增、查看、编辑、删除、筛选通用记录。
- 可以创建、编辑、删除标签，并给记录绑定标签。
- 可以新增任务并修改任务状态。
- 可以新增收入/支出，并查看月度汇总和分类汇总。
- 可以创建、筛选、编辑、删除复盘。
- 可以浏览和搜索 `knowledge/` 下的 Markdown 文件。
- Mobile 可以完成登录、今日概览、快速记录和快速记账。
- CLI 可以完成登录、记录、任务、财务、标签、复盘和知识搜索的基础操作。
- `.\app\scripts\verify.ps1` 可以通过。

## 9. 一期不做什么

为了保证一期能闭环，下面内容暂不进入一期主线：

- 注册和多用户协作。
- 复杂角色权限。
- 社交关系图谱。
- 学习课程系统。
- 工作项目管理系统。
- 生活习惯统计系统。
- 消息推送和提醒。
- AI 自动生成结论。
- 知识库在线编辑和双向同步。

## 10. 下一步开发顺序

建议按下面顺序推进：

1. 固化基础 API 和数据模型。
2. 完成 Web 核心页面闭环。
3. 补齐记录筛选、标签、复盘等 P1 能力。
4. 补齐 Mobile 快速录入和今日视图。
5. 补齐 CLI 自动化入口。
6. 做一次端到端验收，形成一期发布说明。
