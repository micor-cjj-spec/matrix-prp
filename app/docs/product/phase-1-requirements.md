# Phase 1 Requirements

## 需求分级

- P0：一期必须完成，否则闭环不成立。
- P1：一期建议完成，能明显提升可用性。
- P2：可以推迟到二期。

## P0 用户故事

### 登录

作为用户，我希望通过账号密码登录系统，以便访问自己的个人资源数据。

验收：

- 登录成功后获得 JWT。
- 登录失败时显示明确错误。
- 未登录访问业务页面时跳转到登录页。

### Dashboard

作为用户，我希望打开系统第一眼看到今日状态，以便快速决定下一步行动。

验收：

- 展示今日任务数量和列表。
- 展示最近记录。
- 展示本月收入、支出、结余。
- 展示知识库快捷入口。
- 展示财务、任务、记录、知识库模块入口。

### 通用记录

作为用户，我希望能快速记录学习、生活、工作、兴趣等事情，以便沉淀过程数据。

验收：

- 可以新增记录。
- 可以选择模块类型。
- 可以填写标题、内容、日期和标签。
- 可以查看记录列表。
- 可以按模块、日期、关键词筛选。
- 可以编辑和删除记录。

### 任务计划

作为用户，我希望管理待办事项，以便知道接下来要做什么。

验收：

- 可以新增任务。
- 可以设置所属模块、标题、描述、优先级、截止日期。
- 可以切换任务状态：待办、进行中、已完成、已取消。
- 可以查看今日任务和全部任务。
- 可以按状态、模块、日期筛选。

### 财务基础

作为用户，我希望记录收入和支出，以便知道本月钱花在哪里。

验收：

- 可以维护基础账户。
- 可以维护收入和支出分类。
- 可以新增收入/支出交易。
- 交易包含金额、类型、账户、分类、日期、商户/对象、备注。
- 可以查看交易列表。
- 可以按月份查看收入、支出、结余。
- 可以按分类查看支出汇总。

### 知识库浏览

作为用户，我希望在平台里查看已有 Markdown 知识库，以便把原有资料接入新系统。

验收：

- 可以读取 `knowledge/` 目录。
- 可以展示目录树。
- 可以打开 Markdown 文件。
- 可以展示 Markdown 内容。
- 可以按文件名或标题做基础搜索。

## P1 用户故事

### 标签

作为用户，我希望给记录和任务打标签，以便后续检索和归类。

验收：

- 可以创建标签。
- 可以给记录绑定标签。
- 可以按标签筛选记录。

### 财务图表

作为用户，我希望看到简单图表，以便理解消费结构。

验收：

- 展示月度收支趋势。
- 展示支出分类占比。

### 最近活动

作为用户，我希望看到最近操作，以便快速回到最近关注的内容。

验收：

- Dashboard 展示最近新增记录、任务和财务交易。

## P2 用户故事

- App 快速记账。
- CLI 快速新增记录。
- AI 周复盘。
- 知识库在线编辑。
- 社交联系人管理。
- 学习计划管理。

## 体验原则

- 首页必须像工作台，不像营销页。
- 表单字段要少而够用，先让记录动作足够快。
- 列表要支持筛选、搜索和清晰的空状态。
- 财务金额、日期、状态字段要醒目。
- 知识库浏览先保证稳定读取，不追求复杂编辑体验。
